Quarterly records are stored as `<company slug>/<periodEnd>.json` and are separate from the full-year financial reviews.

Use the same quarter a year earlier from the same filing. Check the statement heading, quarter columns, units, scope and audit status. Store the reported values in the source units and explain any sums or definition choices in the source locator. For example, continuing operations covers the businesses still running. Use an official company or exchange filing for the figures, and cite a company operating update when it supports the explanation. Change the checked date only when someone has reviewed the source.

Keep the two comparisons and the explanation short. Label the actual income and profit measures the company reported, including for lenders and insurers. Give readers one concrete thing to look for in the next filing. Submitting a record and deploying it is the publication step. A calendar gap or an exchange search result is not verification.

Run `npm test` to build and verify the bundles. Run `node scripts/watch-quarters.cjs --period=YYYY-MM-DD` for a read-only review queue for the existing profiles. Open the company or exchange source for the period, then verify the actual filing before creating a record. Git keeps the prior record when a filing is corrected or restated.
